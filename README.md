# ✦ KRYVANTA ECOSYSTEM ✦

Единая система для Minecraft-сервера **KRYVANTA** (Paper 1.21.11): сайт с магазином, KRYVANTA VIP,
партнёрская программа блогеров, промокоды, комиссии, бонусы, выплаты, админ-панель и Paper-плагин.
Сайт и плагин связаны защищённым REST API (HMAC-подпись), данные хранятся в PostgreSQL.

```
kryvanta/
├── plugin/   Paper-плагин Kryvanta (Java 21, Maven): префиксы/TAB/скорборд + KRYVANTA VIP
├── web/      Сайт и REST API (Next.js 16, React 19, TypeScript, Tailwind 4, Prisma 6, PostgreSQL)
│   ├── prisma/            схема БД, миграции, seed
│   ├── src/server/        бизнес-логика (заказы, платежи, VIP, блогеры, рефералы, выплаты, API плагина)
│   ├── src/app/           страницы и REST API (/api/...)
│   ├── tests/             интеграционные тесты (vitest + реальный PostgreSQL) и E2E-скрипт
│   └── scripts/           резервное копирование и обслуживание (cron)
└── docs/                  LuckPerms, nginx, systemd, протокол API
```

## 1. Как всё связано

```
 Игрок/блогер/админ ──HTTPS──► Сайт (Next.js) ──► PostgreSQL
                                   ▲   │
       подписанные HMAC-запросы    │   │ очередь доставок (VIP_SYNC, NOTIFY, REWARD_CREDIT, COMMANDS)
                                   │   ▼
                     Paper-плагин Kryvanta ──► LuckPerms (группа kryvanta_vip с временем окончания)
```

* **Оплата** → вебхук провайдера → в одной транзакции: платёж, покупка, комиссия блогеру (25% от
  фактически оплаченной суммы), продление VIP, уведомления, журнал, задание для сервера.
* **Плагин** каждые 30 с забирает с сайта список активных VIP, настройки и очередь доставок, применяет их
  (LuckPerms, награды, сообщения) и подтверждает выполнение. Каждая доставка выполняется ровно один раз.
* **Сайт недоступен?** Плагин работает по последнему кэшу (`sync-cache.json`), VIP снимается
  автоматически самим LuckPerms по времени окончания, события (игровое время, награды) копятся
  в `outbox.json` и отправляются позже.

## 2. Запуск сайта

Требования: **Node.js 22+**, **PostgreSQL 14+**, Linux-сервер (или любой хостинг Node.js).

```bash
cd web
cp .env.example .env          # заполните значения (см. разделы 3–4)
npm ci
npx prisma migrate deploy     # создаёт таблицы, ограничения и триггеры
npm run db:seed               # товары, VIP-функции, наборы наград, первый администратор
npm run build
npm start                     # порт 3000; для постоянной работы — docs/kryvanta-web.service
```

Без своего сервера: **Neon + Vercel**, пошагово в `docs/deploy-vercel-neon.md`.

Сайт должен работать по **HTTPS** за reverse-proxy (пример nginx — `docs/nginx.conf`,
systemd-сервис — `docs/kryvanta-web.service`). В `.env` укажите `APP_URL=https://ваш-домен`.

Обслуживание (cron, каждые 5 минут) — окончание VIP, разморозка комиссий, очистка:
```
*/5 * * * * cd /opt/kryvanta/web && set -a && . ./.env && set +a && npm run expire-vip >> /var/log/kryvanta-maint.log 2>&1
```

Языки: русский и английский (переключатель RU/EN в шапке; выбор сохраняется). Админ-панель — на русском.

Страницы: `/` главная · `/store` магазин · `/checkout/<товар>` оформление · `/vip` · `/rules` ·
`/login` `/register` · `/account` кабинет игрока · `/creator` Creator Program и заявка ·
`/creator/dashboard` кабинет блогера · `/admin` админ-панель · `/r/<КОД>` реферальная ссылка.

## 3. База данных

```bash
sudo -u postgres psql -c "CREATE USER kryvanta WITH PASSWORD 'сложный-пароль';"
sudo -u postgres psql -c "CREATE DATABASE kryvanta OWNER kryvanta;"
# .env:
DATABASE_URL="postgresql://kryvanta:сложный-пароль@127.0.0.1:5432/kryvanta?schema=public"
```

* Миграции: `web/prisma/migrations` (`npx prisma migrate deploy`). Таблицы из ТЗ: `users`,
  `minecraft_accounts`, `vip_subscriptions`, `vip_permissions`, `vip_rewards`, `reward_history`,
  `creators`, `creator_codes`, `referrals`, `referral_events`, `purchases`, `payments`, `commissions`,
  `payout_requests`, `payout_history`, `products`, `settings`, `audit_logs` + служебные
  (`sessions`, `link_codes`, `payment_events`, `plugin_deliveries`, `vip_grant_history`, …).
* Деньги — в копейках (целые числа), проценты — в базисных пунктах (2500 = 25%).
* **Триггеры БД**: `audit_logs`, `payout_history`, `vip_grant_history` — только добавление;
  выплаченные/отклонённые выплаты неизменяемы; сумма начисления неизменяема, удалять начисления нельзя.
  Даже администратор с доступом к БД через приложение не может «тихо» переписать историю.
* **Резервные копии**: `npm run db:backup` (pg_dump + проверка архива + ротация 14 дней).
  Cron: `17 4 * * * cd /opt/kryvanta/web && set -a && . ./.env && set +a && BACKUP_DIR=/var/backups/kryvanta bash scripts/backup.sh`.
  Восстановление: `pg_restore --clean --if-exists --no-owner -d "$URL" файл.dump`.

## 4. Настройка API и платежей

Сгенерируйте секреты: `openssl rand -hex 32` (три раза) → `APP_SECRET`, `PLUGIN_API_SECRET`, `TEST_PAYMENT_SECRET`.
`PLUGIN_API_SECRET` также вписывается в `plugins/Kryvanta/config.yml → api.secret`.

**Платёжный провайдер** (`PAYMENT_PROVIDER`):

| Значение | Что происходит |
|---|---|
| `manual` (по умолчанию) | Заказ ждёт подтверждения: `/admin → Покупки → «Подтвердить оплату»`. Подходит, пока провайдер не подключён. |
| `test` | Тестовая страница оплаты `/pay/test/...` + подписанный HMAC вебхук. В production работает только с `ALLOW_TEST_PAYMENTS=true` — **не включайте его на боевом сайте**. |
| `yookassa` | ЮKassa API v3. Нужны `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`. В личном кабинете ЮKassa укажите HTTP-уведомления на `https://ваш-домен/api/webhooks/yookassa` с событиями `payment.succeeded`, `payment.canceled`, `refund.succeeded`. |

Защита платежей: идемпотентный ключ на каждый платёж, уникальность `(provider, providerPaymentId)`,
журнал обработанных событий `payment_events`, условное обновление статуса (повторный/параллельный
вебхук не начислит VIP и комиссию дважды), сверка суммы. У ЮKassa уведомления не подписываются,
поэтому сайт принимает их только с IP ЮKassa и **всегда перепроверяет статус и сумму через API ЮKassa**.
Интеграция с ЮKassa написана по официальной документации, но не проверялась на реальном магазине —
перед запуском проведите тестовый платёж в тестовом магазине ЮKassa.

Другой провайдер подключается реализацией интерфейса `PaymentAdapter` (`web/src/server/payments/types.ts`)
и вебхука по образцу `webhooks.ts`.

## 5. Плагин и подключение Minecraft-сервера

**Сборка.** GitHub → вкладка **Actions** → workflow `build` → артефакт **Kryvanta** (jar).
Локально: JDK 21 + Maven, `cd plugin && mvn package` → `plugin/target/Kryvanta-2.0.0.jar`.

**Установка.**
1. Установите **LuckPerms 5.4+** (Bukkit-версию).
2. Положите `Kryvanta-2.0.0.jar` в `plugins/`, перезапустите сервер.
3. В `plugins/Kryvanta/config.yml`:
   ```yaml
   api:
     url: "https://ваш-домен"          # APP_URL сайта
     secret: "значение PLUGIN_API_SECRET"
   ```
4. `/kryvanta reload`, затем `/kvip status` — должно быть «сайт доступен».

Плагин заменяет TAB/чат/скорборд-плагины (как и раньше) и показывает VIP-префикс из LuckPerms в чате,
TAB и над головой. Не ставьте вместе с ним TAB, EssentialsXChat, ChatControl.

**Совместимость с Essentials.** У EssentialsX есть свои `/ec`, `/craft`, `/anvil` и др. EssentialsX
по умолчанию уступает такие команды другим плагинам, поэтому сработают команды Kryvanta.
Проверьте, что этих команд **нет** в списке `overridden-commands` в `plugins/Essentials/config.yml`.
Полная форма работает всегда: `/kryvanta:ec`.

**Команды игроков**: `/vip` `/size` `/boat` `/ec` `/anvil` `/craft` `/enchant` `/grindstone` `/smithing`
`/loom` `/stonecutter` `/cartography` `/brew` `/viprewards` `/vipsettings` `/link <код>` (все с автодополнением).
**Администрации**: `/kvip status|sync|info <игрок>`, `/kryvanta reload`, `/prefix …`.

**Привязка аккаунта**: кабинет на сайте → «Получить код привязки» → в игре `/link КОД` (10 минут,
одноразовый). Владение аккаунтом доказывает именно ввод команды в игре. **Важно:** на сервере в
`online-mode=false` без прокси с авторизацией кто угодно может зайти под чужим ником — тогда привязка
не доказывает владение. Используйте `online-mode=true` или Velocity/BungeeCord с проверкой.

**Что делает VIP в игре** (без PvP-преимуществ, полёта, бессмертия, телепортации, админ-команд, OP):

* `/size` — 0.5x…2.0x через атрибут `minecraft:scale` (хитбокс, камера, высота глаз меняются честно).
  Увеличение запрещено, если новый хитбокс задевает блоки; в PvP-бою размер на 15 с возвращается к 1.0x;
  при окончании VIP — сброс. Набор размеров настраивается в админ-панели.
* `/boat` — уровни I–III. Только лодка, которой управляет сам VIP, только на воде (не на льду),
  только при нажатом «вперёд»; скорость плавно растёт до потолка уровня и не превышает его.
* `/anvil` `/craft` `/grindstone` `/smithing` `/loom` `/stonecutter` `/cartography` — настоящие
  серверные меню; ремонт, объединение, переименование и опыт считает сам сервер; предметы
  из слотов возвращаются при закрытии.
* `/enchant` — настоящий стол зачарования с силой **15 полок (уровень 30)**: стоимость по ванильному
  алгоритму, зачарования выбирает ванильный `EnchantmentHelper`, опыт и лазурит списывает сервер.
* `/ec` — личный эндер-сундук игрока.
* `/brew` — личная варочная стойка (ванильные рецепты 1.21, 400 тиков, огненный порошок на 20 варок);
  содержимое сохраняется; варка идёт, пока игрок онлайн; после окончания VIP содержимое возвращается.
* `/viprewards` — каждые 3 ч **активной** игры набор ресурсов (обычный 70% / редкий 25% / эпический 5%,
  всё меняется на сайте). AFK не считается: время идёт только при повороте камеры, ходьбе с нажатыми
  клавишами, ломании/установке блоков, чате, командах и т.д.; поток воды без нажатия клавиш и
  повторяющийся макрос-поворот не засчитываются. Прогресс сохраняется после перезапуска; накопить можно
  не более N наград. Выдача: проверка места → списание награды → сохранение → предметы → журнал на сайте
  (уникальный claimId, дубли невозможны).

## 6. LuckPerms

Плагин сам создаёт группу `kryvanta_vip` при запуске: разрешения `kryvanta.vip.*`, префикс
(`&#d4af37&l✦ VIP`, меняется на сайте), вес 20, явный запрет `kryvanta.admin`. Любые другие узлы
(наследование групп, чужие права) из этой группы удаляются при каждом запуске. VIP выдаётся игроку
**временным** членством в группе — LuckPerms снимет его сам в момент окончания.

Ручная настройка (если нужно сделать то же самое командами) — `docs/luckperms.md`.
Проверка конфликтов: `/lp group kryvanta_vip info`, `/lp user <ник> info` — у VIP должна быть
только группа `default` + `kryvanta_vip` с датой окончания. Не делайте `kryvanta_vip` родителем
других групп и не выдавайте игрокам OP.

## 7. Первый блогер и промокод

1. Блогер регистрируется на сайте и подаёт заявку на `/creator` (или вы добавляете его сами).
2. `/admin → Заявки → Одобрить` (можно задать промокод) **или** `/admin → Блогеры → Добавить`
   (email / имя на сайте / ник Minecraft + имя и промокод).
3. Дополнительные промокоды: `/admin → Промокоды → Создать` (скидка, лимит, срок, «одно использование
   на аккаунт»). Там же статистика применения и отключение.
4. Индивидуальные условия: `/admin → Блогеры → (раскрыть) → комиссия %, бонус за игрока`.
5. Блогер видит всё в `/creator/dashboard`: промокод, ссылку `https://домен/r/КОД`, переходы,
   приглашённых и активных игроков, продажи, графики, баланс, операции и выплаты.

Правила: комиссия начисляется **только после подтверждённой оплаты**, от **фактически оплаченной**
суммы (199 ₽ − 10% = 179,10 ₽ → 25% = 44,77 ₽), «замораживается» на `holdDays` (по умолчанию 7 дней)
и отменяется при возврате. Свой промокод блогер применить не может. Активный игрок = зарегистрировался
по коду, привязал аккаунт, наиграл 3 ч активного времени, не с IP блогера, не массовая регистрация с
одного IP, Minecraft-аккаунт не привязывался ранее к другому профилю. Бонусы за 10/25/50/100 активных
игроков начисляются один раз. Уровни Bronze/Silver/Gold/Diamond — по продажам за месяц (лучший из
текущего и прошлого), пороги и надбавки — в `/admin → Настройки`.

## 8. Проверка покупки

Локальный стенд (тестовый провайдер):
```bash
cd web
# в .env: PAYMENT_PROVIDER=test
npm run build && ALLOW_TEST_PAYMENTS=true npm start
```
1. Зарегистрируйтесь, в кабинете получите код и привяжите аккаунт `/link КОД` в игре.
2. `/store → KRYVANTA VIP → промокод → «Перейти к оплате» → «Оплатить (тест)»`.
3. Заказ станет «Оплачен»; в `/admin → Покупки` видно комиссию; через ≤30 с в игре придёт сообщение,
   игрок получит группу `kryvanta_vip`, префикс и команды. `/kvip info <ник>` покажет срок.
4. Возврат: `/admin → Покупки → Возврат` → комиссия отменяется, срок VIP уменьшается.

В режиме `manual`: заказ → `/admin → Покупки → Подтвердить оплату`.

## 9. Тест выплаты

1. Сделайте несколько покупок по промокоду блогера.
2. Комиссии доступны к выводу после `holdDays` (для теста поставьте 0 в `/admin → Настройки`;
   уже созданные начисления разморозятся по своей дате).
3. Блогер: `/creator/dashboard → Запросить выплату` (сумма ≥ минимальной, ≤ доступного; одна открытая заявка).
4. Админ: `/admin → Выплаты → Одобрить` (можно с меньшей суммой) → переведите деньги вручную →
   «Отметить как выплаченную» с ID банковской операции (ID уникален — двойная выплата невозможна).
5. История переходов видна под заявкой и в `/admin → Журнал`; изменить выплаченную заявку нельзя.

## 10. Выдача VIP вручную

`/admin → VIP → Выдать / продлить` (ник Minecraft, дни, причина). Там же «Сократить срок»,
«Снять полностью», цена и срок VIP (`priceKopecks`, `durationDays` — изменения не затрагивают
уже оформленные заказы), включение/отключение команд, настройки размеров/лодки/наград (JSON),
список активных VIP и история выдачи. Награды: `/admin → Награды` (наборы, вес, предметы
по именам Bukkit Material, ручная выдача, история, прогресс игроков).

## 11. Безопасность

* Пароли — bcrypt (cost 12); сессии — случайный токен в httpOnly-cookie, в БД только HMAC-хэш.
* Роли PLAYER / CREATOR / ADMIN проверяются на каждом API-запросе и странице.
* CSRF: SameSite=Lax + обязательный совпадающий `Origin` + `Content-Type: application/json` для всех изменяющих запросов.
* SQL-инъекции: только Prisma с параметрами; XSS: React экранирует вывод, сообщения в игре —
  через `Placeholder.unparsed`; заголовки безопасности (`X-Frame-Options`, `nosniff`, …).
* Rate limiting: вход, регистрация, промокоды, заказы, коды привязки, выплаты, вебхуки
  (в памяти процесса — для нескольких инстансов замените на Redis, `src/lib/ratelimit.ts`).
* API плагина: HMAC-SHA256 подпись запроса и ответа, timestamp ±5 мин, одноразовый nonce (защита от повтора).
  Секрет хранится только в `.env` и `config.yml`, по сети не передаётся.
* IP-адреса хранятся только в виде HMAC-хэшей. Если сайт не за reverse-proxy, задайте `TRUST_PROXY=false`
  (тогда IP-проверки рефералов отключаются, вместо того чтобы всех считать одним IP).
* Журнал действий администраторов и системы — неизменяемый (триггеры БД).


Покрыто автоматически: покупка VIP, скидка 10%, комиссия 25% от оплаченной суммы, привязка покупки к
блогеру, бонус за активного игрока и за достижения, повторные/параллельные вебхуки, продление VIP,
окончание через 30 дней и команда серверу снять группу, возврат, лимиты/срок/отключение промокодов,

**GitHub Actions → job `server-smoke`** при каждом push поднимает PostgreSQL и сайт, скачивает

группа `kryvanta_vip` создана с правильными правами и префиксом, связь с сайтом по подписанному API есть,
VIP, выданный на сайте, появляется у игрока в LuckPerms, а после отзыва — снимается.

## 13. Что требует внешних сервисов

* **Реальный приём платежей** — нужен договор с провайдером (ЮKassa реализована). До этого — `manual`.
* **Выплаты блогерам** — сайт ведёт учёт и статусы, сами деньги переводит администратор (банк/СБП),
  затем вводит ID операции.
* **Онлайн сервера** на сайте берётся из heartbeat плагина (раз в 30 с).
* **Аватары игроков** в кабинете загружаются с `mc-heads.net` по UUID.
